## 验证环境

本机为macOS ARM，后端使用独立准备的JDK17与项目附带的Maven3.9.9，数据库为独立MySQL9.6.0实例。测试前端为 `http://localhost:5173`，测试后端为 `http://localhost:18080/api`，测试数据库端口13307。README中的8080/3306是常规部署默认值，不是本次独立测试实例端口。

测试数据库与原有MySQL实例数据分离。HTTP脚本会创建演示工单、日志和临时用户，不用于生产环境；它保留完成的报修记录作为演示数据。正式使用时按README连接自己的数据库。

## 已验证的核心行为

- 系统管理员新增用户、查询确认、修改姓名、删除后再次查询确认。
- BCrypt哈希保存密码，响应不返回密码哈希；初始化账号实际可用 `password` 登录。
- 匿名访问401；学生管理用户403；学生发布公告403；缺少必填表单400。
- 无CSRF登录403；伪造JWT401；单元测试拒绝过期JWT与弱密钥。
- 禁用账号拒绝访问；允许来源的CORS预检成功，非允许来源拒绝。
- 最后一个系统管理员不能通过编辑角色绕过保护。
- 学生提交报修、管理员审核派单、维修人员开始与完成、学生评分确认；最终状态COMPLETED。
- 已完成工单不能取消；退出后当前浏览器身份接口401。
- 浏览器HttpOnly、SameSite=Lax Cookie，localStorage不保存令牌或用户身份；刷新恢复登录，退出后刷新不恢复。
- Swagger页面与实际生成的OpenAPI JSON可访问。

## 本次修复的问题

1. 自定义两段Token改为标准JWT，由Spring Security过滤器验证。
2. 引入权限表和角色权限关联，使用数据库权限及方法角色控制访问。
3. JWT不再通过登录JSON返回，也不在浏览器localStorage中保存；用HttpOnly Cookie传递。
4. 写请求每次先获取当前CSRF Token，避免认证后旧Token失效导致403。
5. 初始化SQL中原演示哈希与文档密码不匹配，已改为实际BCrypt生成并验证可登录的哈希。
6. 数据库连接密码与JWT签名密钥改由环境读取；不返回服务器内部错误或参数原值。
7. 修复“编辑用户”绕过最后一个管理员保护的路径。
8. 修复较窄屏幕上表格溢出面板、覆盖相邻表单的问题。
9. 重装本机依赖并更新锁文件，使前端在macOS ARM构建通过。

## 验证范围

本记录不宣称所有既有管理功能都经过穷尽测试。宿舍、公告、统计等既有页面与接口保留，当前重点是课程一、二、四要求和报修主流程。没有实现模型调用、RAG或模型提示注入链路，因此不把普通输入校验标成AI提示注入测试。

现有数据库升级只执行权限迁移，不会自动重置已有用户密码。若旧演示账号受原错误哈希影响，应通过管理员密码重置功能处理；全量初始化只适用于可清空的独立数据库。

## 复现

按README设置JDK17、数据库和JWT_SECRET后：

```bash
cd backend
mvn clean verify
java -jar target/dorm-repair-backend-1.0.0.jar
```

另一终端运行前端，再在项目根目录执行：

```bash
python3 scripts/verify_api.py --base http://localhost:8080/api --allow-write
```

安全实现参考 [Spring Security CSRF文档](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)，接口文档使用 [springdoc官方项目](https://springdoc.org/)。实际验证以本次源码和证据文件为准。
